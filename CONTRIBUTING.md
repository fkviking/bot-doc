# Как редактировать документацию

Работа с документацией ведется в `assets/ru/` и `assets/en/`.

| Что нужно изменить | Где редактировать |
| --- | --- |
| Текст, заголовок и описание страницы | [`assets/ru/`](assets/ru/) и [`assets/en/`](assets/en/) |
| Порядок страниц в боковом меню, подписи и тексты AI-индексов | [`src/.vuepress/config.js`](src/.vuepress/config.js) |
| Изображения | [`assets/00-img/`](assets/00-img/) |
| Видео и обложки для видео | [`assets/00-video/`](assets/00-video/) |

## Быстрый маршрут

1. Найдите страницу в `assets/ru/` или `assets/en/`. Для обеих версий используется одно и то же имя файла.
2. Измените исходный текст и, если нужно, соответствующую страницу другого языка.
3. Запустите `yarn build`. Сборка сгенерирует страницы и проверит обязательные поля, якоря, AI-версии и видео.
4. Проверьте изменённую страницу на локальном сайте или в собранном `src/.vuepress/dist/`.

## Изменить существующую страницу

Пишите заголовки обычным Markdown и не добавляйте номера вручную. Нумерация автоматически генерируется:

| Заголовок в исходном файле | Номер после генерации |
| --- | --- |
| Первый `#` | `1.` |
| Первый `##` | `1.1.` |
| Первый `###` | `1.1.1.` |
| Следующий `##` | `1.2.` |
| Первый `###` под ним | `1.2.1.` |
| Следующий `###` | `1.2.2.` |

Если указано `ignore-section-number: true`, номера к заголовкам этой страницы не добавляются.

Имена параметров, элементов интерфейса и короткие формулы, данные без ссылки, выделяйте обратными кавычками: `LOCAL`, `#p.sell`.

Если меняете содержание раздела, проверьте его `summary` в начале файла: это описание публикуется в `llms.txt` и `sitemap.md` на языке страницы.

## Добавить или переставить раздел

1. Создайте Markdown-файлы с одинаковым именем в `assets/ru/` и `assets/en/`.
2. Добавьте в начало каждого файла YAML-метаданные. Например:

   ```yaml
   ---
   title: 2. О платформе
   section: 2
   summary: Устройство платформы, системные требования и ролевая модель.
   ---
   ```

3. Добавьте имя файла без `.md` в списки `sidebar` для нужных языков в [`src/.vuepress/config.js`](src/.vuepress/config.js).
4. Если меняете порядок страниц, обновите `title` и `section` у затронутых разделов.
5. Запустите `yarn build`. Без `summary` сборка остановится и укажет файл, в котором его не хватает.

| Поле | Назначение |
| --- | --- |
| `title` | Название и номер раздела в боковом меню. |
| `section` | Номер раздела, от которого рассчитывается нумерация заголовков. |
| `summary` | Обязательное описание одним предложением на языке страницы для `llms.txt` и `sitemap.md`. |
| `ignore-section-number` | Необязательное поле. Значение `true` отключает автоматическую нумерацию заголовков этой страницы; при `false` или отсутствии поля нумерация включена. |

## Добавить изображение

Поместите файл в `assets/00-img/`. В тексте страницы используйте путь `@images/` и осмысленное описание изображения:

```md
![Схема робота](@images/bot-scheme.svg)
![Иконка справки](@images/icons/help.svg)
```

Для изображения с английскими надписями положите отдельный файл в ту же папку и используйте его в английской странице, например `@images/bot-scheme-en.svg`.

> [!NOTE]
> Пути `@images/` и `@videos/` используются в исходниках страниц документации.

## Добавить видео

1. Поместите MP4, WebM или OGV в `assets/00-video/`. Имя файла должно состоять из латинских букв, цифр, дефисов или подчёркиваний; размер — меньше 100 МБ.
2. Добавьте ссылку на видео отдельным абзацем страницы:

   ```md
   [Описание параметра Quote](@videos/quote.mp4)
   ```

3. Если нужна своя обложка, положите её рядом с видео и добавьте `.preview` перед расширением:

   ```text
   quote.mp4
   quote.preview.jpg
   ```

Поддерживаются обложки JPG, JPEG, WebP и PNG. При сборке ссылка превращается в плеер, а видео и обложка публикуются вместе с документацией. Если обложки нет, она создаётся автоматически.

## Сослаться на страницу или заголовок

Для ссылки между страницами пишите имя исходного файла. Расширение `.md` предпочтительнее: редактор сможет подсказывать заголовки.

```md
[Описание параметров](params-description.md)
[Параметр Sell](params-description.md#p.sell)
```

Ссылка на `.html` также поддерживается. В исходных файлах используйте текущие имена страниц без числового префикса: `params-description.md`, `faq.md`.

При генерации заголовкам добавляются якоря `<Anchor :ids="[...]" />`. Русские заголовки переводятся в транслит, а ссылки на них преобразуются при сборке.

### Найти якорь заголовка

- Если страница уже опубликована, нажмите **#** рядом с заголовком и скопируйте часть адреса после `#`.
- Если страница новая, запустите `yarn pre-process` (или `npm run pre-process`) и найдите якорь в `src/docs/имя-файла.md` либо `src/en/docs/имя-файла.md`.

Например, для заголовка `Краткое описание робота` в `introduction.md` задан якорь `robot_short`. Ссылка на него: `introduction.md#robot_short`.

<details>
<summary>Как сослаться на заголовок, написанный по-русски</summary>

В исходном Markdown можно написать ссылку с русским заголовком. При генерации её фрагмент будет транслитерирован:

```md
[Горячие клавиши](getting-started.md#горячие-клавиши)
```

После `yarn pre-process` проверьте результат в сгенерированном файле.

</details>

### Поставить якорь вручную

Добавьте `<Anchor>` в нужное место исходного Markdown-файла:

```md
<Anchor :ids="['portfolio_example']" />
```

Теперь на это место можно сослаться как `имя-файла.md#portfolio_example`. На сайте рядом с якорем появится кнопка **#** для копирования ссылки. Если кнопка не нужна, добавьте `hide`:

```md
<Anchor hide :ids="['portfolio_example']" />
```

> [!WARNING]
> Используйте в `ids` латинские символы или транслит без пробелов. Имя якоря должно быть уникальным в пределах файла. Например, `tc.HUOBI.ws_url` подходит, а `tc.HUOBI api url` содержит пробел. При повторяющемся имени или пробеле `yarn build` завершится с ошибкой и покажет проблемный файл и якорь.

Для однотипных полей разных бирж добавляйте префикс биржи, например `tc.IMEX.binary_protocol_gateway`.

## Поддерживать английскую версию

- Редактируйте переводы в `assets/en/`; русские исходники находятся в `assets/ru/`.
- Сохраняйте одинаковые имена файлов и соответствующую структуру разделов в обеих версиях. При изменении порядка проверьте `section` и списки `sidebar` для каждого языка.
- Заполняйте `title` и `summary` на языке страницы.
- Для изображений с надписями подготовьте отдельную английскую версию в `assets/00-img/`.

## Обновить AI-версии документации

При сборке каждая опубликованная страница получает Markdown-копию. Индексы и карты создаются автоматически:

```text
docs/faq.html   — страница на сайте
docs/faq.md     — та же страница в Markdown
llms.txt        — краткая карта документации
llms-full.txt   — все страницы в одном файле
sitemap.md      — страницы и разделы со ссылками на якоря
sitemap.xml     — карта сайта для поисковых роботов
```

Для английского языка те же файлы публикуются в `en/`. На странице есть кнопка **Копировать страницу**, просмотр Markdown и открытие текста в ChatGPT, Claude или DeepSeek; ссылки на `llms.txt` и `sitemap.md` также доступны в подвале.

Чтобы изменить данные AI-версий:

| Что меняется | Где править |
| --- | --- |
| Заголовок, описание и текст страницы | `title`, `summary` и Markdown в `assets/ru/` или `assets/en/`. |
| Порядок страниц | Списки `sidebar` в `src/.vuepress/config.js`. |
| Подписи кнопки и формулировки индексов | `copyPage` и `aiDocs` в `src/.vuepress/config.js`. |
| «Примечания» в `llms.txt` | `aiDocs.ru.notes` и `aiDocs.en.notes` в `src/.vuepress/config.js`; заголовки — в `notesTitle`. |

Отдельный список страниц для `llms.txt` и `sitemap.md` вести не нужно. При добавлении раздела достаточно заполнить `summary` в обоих файлах и добавить страницу в соответствующие списки `sidebar`. Текст не редактируется в `scripts/generate-ai-docs.js` или в сгенерированных файлах.

### Написать примечание для `llms.txt`

Примечания объясняют то, чего не видно из описания отдельной страницы: как читать документацию целиком и где легко ошибиться. Русский и английский списки ведутся отдельно и не обязаны совпадать построчно.

- Проверяйте каждое утверждение по странице документации, на которую оно опирается.
- Не повторяйте `summary` отдельной страницы.
- Пишите названия параметров и статусов точно как в роботе, в обратных кавычках: `LOCAL`, `#p.sell`.
- Держите список коротким — около четырёх–пяти пунктов. Вопросы FAQ уже опубликованы отдельными ссылками в `sitemap.md`.

Вопросы FAQ попадают в `sitemap.md` из якорей `<Anchor :ids="[...]" />` внутри `<summary>`. Добавьте вопрос с уникальным якорем — отдельный список вопросов поддерживать не требуется.

<details>
<summary>Как формируются опубликованные файлы</summary>

Порядок страниц берётся из `sidebar` в `src/.vuepress/config.js`, заголовок и описание — из `title` и `summary`, а текст — из сгенерированных `src/docs/` и `src/en/docs/` с готовой нумерацией. В `<head>` каждой страницы добавляются ссылки на её Markdown-копию и `llms.txt`.

</details>

## Запустить и проверить локально

Установите зависимости и запустите локальный сервер:

```bash
yarn install
NODE_OPTIONS=--openssl-legacy-provider yarn dev
```

Перед завершением работы запустите полную сборку:

```bash
yarn build
```

Она генерирует страницы, AI-файлы и видео, затем запускает проверки. Чтобы отдельно проверить уже собранный `src/.vuepress/dist/`, выполните:

```bash
yarn test:ai-docs
```
