История изменений

#
#
2026-11-10 Несовместимые изменения

  • Добавлена возможность настраивать расписание торговли портфеля отдельно для каждого дня недели, в связи с этим:
    • Удален параметр портфеля TradingDays;
    • Добавлен столбец Trading days в таблицу с расписанием Timetable портфеля;
    • Удален пункт Group TradingDays в меню Actions виджета Portfolios table.
  • Добавлена возможность настраивать расписание рассчета значений индикаторов отдельно для каждого дня недели, в связи с этим:
    • В C++ интерфейс в объект interval добавлен новый конструктор, учитывающий дни недели;
    • В C++ интерфейс в объект schedule добавлен новый перегруженный метод is_in, учитывающий день недели.
  • В связи с удалением параметра портфеля TradingDays и с добавлением его в каждый интервал в таблице с расписанием Timetable портфеля:
    • Если данный параметр как-то использовался через WebSocket API, необходимо изменить реализацию клиентского кода, т.к. изменения в роботе НЕ сохраняют обратную совместимость;
    • Текущие настройки ВСЕХ портфелей также НЕ сохраняют обратную совместимость, во все интервалы в расписании в качестве значения Trading days по умолчанию будут проставлены все дни недели, пользователям придется самим изменить дни на нужные для всех интервалов всех портфелей.

#
#
Как перейти

#
#
WebSocket API

Поле trading_days убрано из объекта портфеля и добавлено в каждый элемент массива timetable. Формат значения не изменился: битовая маска дней недели (bitmask_select), 1 - воскресенье, 2 - понедельник, 4 - вторник, 8 - среда, 16 - четверг, 32 - пятница, 64 - суббота, значение по умолчанию 127 (все дни), описание полей смотрите в api.md и в Timetable.

На уровне портфеля:

Было Стало
{
  "trading_days": 127,
  "name": "qwe",
  "decimals": 4,
  "securities": { … },
  "timetable": [ … ],
  // …
}

{
  "name": "qwe",
  "decimals": 4,
  "securities": { … },
  "timetable": [ … ],
  // …
}

На уровне расписания (timetable):

Было Стало
{
  "begin": 36000,
  "end": 67200,
  "a_sell": 2,
  "a_buy": 2,
  "auto_close": false,
  "auto_to_market": false,
  "auto_to0": 2,
  "save_history": false
}

{
  "trading_days": 127,
  "begin": 36000,
  "end": 67200,
  "a_sell": 2,
  "a_buy": 2,
  "auto_close": false,
  "auto_to_market": false,
  "auto_to0": 2,
  "save_history": false
}

Если клиент читал или записывал trading_days портфеля, теперь нужно:

  • читать trading_days из каждого интервала timetable портфеля, а не из самого портфеля;
  • записывать trading_days в каждый интервал timetable: поле обязательное (например, понедельник-пятница это 2 + 4 + 8 + 16 + 32 = 62); допустимый диапазон от 1 до 127;
  • не передавать trading_days на уровне портфеля: запрос с этим полем будет отклонён с ошибкой.
#
#
Существующие портфели

У всех существующих портфелей во всех интервалах timetable значение trading_days будет 127 (все дни недели). Прежнее значение портфеля не переносится, пользователям нужно самим задать Trading days для каждого интервала.

#
#
C++

В interval добавлен конструктор с битовой маской дней недели:

interval(int trading_days, day_time b, day_time e)

Должны выполняться условия b < e и 1≤trading_days≤1271 \le trading\_days \le 1271≤trading_days≤127, иначе будет выброшено std::invalid_argument. Прежний interval(day_time b, day_time e) работает как раньше и задает все дни недели.

В schedule добавлен перегруженный метод is_in:

bool is_in(int wd, const day_time& dt) const

wd - день недели, 0≤wd≤60 \le wd \le 60≤wd≤6 (0 - воскресенье, 1 - понедельник и т.д.); как и is_in(const day_time& dt), метод возвращает true, если расписание пусто.
